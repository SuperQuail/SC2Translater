# 工作区改造计划：以文件夹为单位，完全对齐 VS Code

> 状态：**计划，未实施**。写于 2026-10-09。
>
> 前端部分的每一步都要先按 `AGENTS.md` 第 8 节出预览图、拿到明确同意再写代码。

---

## 1. 要解决什么

现在是「项目文件」模型：用户存一个 `.sc2transproj`，里面列着**绝对路径**的地图。三个问题：

1. **不 VS Code**。VS Code 的单位是**文件夹**：打开文件夹 -> 左边就是这棵树的真实结构，
   `Ctrl+Shift+E` 看它、`Ctrl+P` 跳文件。我们这边是个扁平列表，跟磁盘结构没有对应关系。
2. **不能搬**。绝对路径写死在项目文件里，文件夹一挪、换台机器，全断。
3. **状态没地方放**。术语库、版本仓库、扫描统计现在散在项目文件旁边（`<项目名>.glossary.json`、
   `<项目名>.repos/`），文件夹里多出一堆我们的杂项文件。

改成：**打开文件夹 = 打开工程**。我们的数据全部收进 `<文件夹>/.sc2translater/`。

## 2. 目录约定

```
斯托科夫战役/                 <- 你打开的这个文件夹，就是工程根
├─ Maps/
│  ├─ Stukov2.SC2Map         <- 我们要处理的东西，就地放着不动
│  └─ Stukov3.SC2Map
├─ Mods/
│  └─ SCMR.SC2Mod
└─ .sc2translater/           <- 我们的，全部数据在这里
   ├─ workspace.json         <- 工作区清单（见第 3 节）
   ├─ glossary.json          <- 项目术语库（原 <项目名>.glossary.json）
   ├─ cache/
   │  └─ stats.json          <- 扫描统计缓存，随时可删，删了只是重扫
   ├─ repos/                 <- 每个文档一个 SC2Diff 仓库（原 <项目名>.repos/）
   │  └─ Maps__Stukov2/
   └─ .gitignore             <- 自动生成，内容就一行：cache/
```

约定：

* **只新增，不改用户的东西**。地图/模组原地不动；我们只往 `.sc2translater/` 写。
* `workspace.json` 里的路径**一律相对工程根**。整个文件夹打包发给别人，打开就能用。
* `cache/` 是可再生的，所以单独一个文件 + 自带 `.gitignore`，用户把它提交进 git 也不会脏。
* 资源管理器里 `.sc2translater` 显示为**暗色**（跟 VS Code 显示 `.git` 一个待遇），不展开。

## 3. `workspace.json` 长什么样

```json
{
  "format": 1,
  "name": "斯托科夫战役",
  "defaults": { "source": "enUS", "target": "zhCN" },
  "files": [
    {
      "path": "Maps/Stukov2.SC2Map",
      "label": "",
      "source": "enUS",
      "target": "zhCN",
      "output": "Maps/Stukov2.zhCN.SC2Map"
    }
  ],
  "open": ["Maps/Stukov2.SC2Map", "Maps/Stukov3.SC2Map"],
  "active": 0,
  "view": {
    "activity": "explorer",
    "left": true, "right": true,
    "left_width": 252, "right_width": 360,
    "density": "standard", "tab_view": "table"
  },
  "created_at": "...", "updated_at": "..."
}
```

变化点（相对现在的 `Project`）：

| 现在 | 改成 | 为什么 |
| --- | --- | --- |
| `path` 是绝对路径 | 相对工程根的路径 | 可搬移 |
| `stats` 存在文件条目里 | 挪到 `cache/stats.json` | 统计每次扫描都变，别把主文件写脏 |
| 视图偏好存在浏览器 localStorage | 存进 `view` | 换机器、发给同事，布局跟着走 |
| `active: usize` | `open[] + active` | 对应 VS Code 的「打开的编辑器」标签组 |
| 项目文件在文件夹外面 | `.sc2translater/workspace.json` | 数据收口 |

## 4. 交互

### 4.1 主界面（照 VS Code）

| VS Code | 我们 |
| --- | --- |
| `File > Open Folder…`（`Ctrl+K Ctrl+O`） | 同样，`Ctrl+K Ctrl+O` |
| 资源管理器是一棵真实的文件夹树 | 同样，根节点 = 文件夹名 |
| 标题栏 `● 文件 — 文件夹 — 应用名` | 同样（`●` 表示有未保存改动） |
| Explorer 工具栏：新建/刷新/折叠 | 刷新 / 折叠全部 / 添加文件（**不做新建删除**，见第 7 节） |
| `.git`、`.vscode` 暗色显示 | `.sc2translater` 暗色显示 |
| 标签条 = 打开的编辑器 | 同样，`open[]` 就是标签组 |

树里显示什么：**文件夹 + 我们认得的文件**（`.SC2Map` / `.SC2Mod`），其余文件默认不显示。
大工程里塞满 `.xml`、`.dds` 只会淹掉真正要处理的东西。
（这是默认值，如果希望像 VS Code 那样显示全部，那是第 8 节里的一个待选项，要先出图。）

#### 4.2.0 颜色与控件从哪来（不是照着色号猜的）

它的组件是 React 写的，我们不会为了一个开始页把 React 拖进来；
但它的**样式表是纯 CSS + CSS 变量**，所以直接采用它的**设计令牌**：

| 用途 | 令牌 | 值 |
| --- | --- | --- |
| 页面底色 | content background | `#1E1F22` |
| 侧栏 / 次级底 | sidebar background | `#2B2D30` |
| 分隔线 | line | `#43454A` |
| 正文 | text | `#DFE1E5` |
| 次要文字 | secondary | `#9DA0A8` |
| 提示 | hint | `#868A91` |
| 主色 / 高亮 | main | `#3574F0` |
| 选中底 | selected background | `#2E436E` |
| 悬停底 | hover background | `#25324D` |
| 间距基准 | unit | `8px` |

来源：Ring UI 包里的 `components/global/variables_dark.css`（暗色主题的全套变量）。
字体用 JetBrains Sans（专有，不随包发）的**官方回退链**：`system-ui, Segoe UI`。

#### 4.2.2 顶部两个动作

| 按钮 | 干什么 |
| --- | --- |
| **新建项目…** | 选一个文件夹，在里面建 `.sc2translater/`。空文件夹、非空文件夹都能建（非空时只往里加我们的目录，不动别的） |
| **打开…** | 选文件夹；有 `.sc2translater/` 直接开，没有就新建（若是老的 `.sc2transproj` 目录则先走第 6 节的迁移） |

#### 4.2.3 为什么只有两个动作

参考图里第三项是 `Clone Repository`。**我们没有远端** —— 版本管理是内置 SC2Diff 的本地
git 形状仓库，没有 remote。所以不做第三项，也不拿别的东西凑数。

那老的 `.sc2transproj` 怎么进来？走「打开…」：打开那个文件夹时发现老项目文件，按第 6 节迁移。
少一个按钮，少一条要维护的路径。

#### 4.2.4 最近列表存哪

> `%APPDATA%/net.miyin.sc2trans/recent-folders.json`
>
> **不进工程文件夹** —— 它是跨工程的全局状态，塞进某个工程里就跟着那个工程跑了。

字段：绝对路径、显示名、最后打开时间、地图数量、是否有版本仓库 / 术语库。
最多记 20 条；刷新时过滤掉已不存在的路径，但**保留并标成「路径已失效」** ——
外接盘拔了不等于用户不要了（JetBrains 也是这么处理的）。

#### 4.2.5 参考图为什么不进 git

参考图是**别人的 IDE 截图**，里面是别人机器的真实目录结构（还带私人项目名）。
这个仓库是 MIT、要发出去的，把这种东西提交进去既没用也不合适。所以约定：

* 参考图放 `refs/`，`.gitignore` 里已经有 `/refs/`；
* 计划与文档**只引用路径**，不把图嵌进仓库；
* 同样的规矩适用于以后所有参考截图、别人的界面录屏、临时对比图；
* 只有**我们自己产物的截图**才进 `docs/design/`。

## 6. 迁移与兼容

三条路都要通：

1. **打开一个已经有 `.sc2translater/` 的文件夹** —— 直接读，正常路径。
2. **打开一个没有 `.sc2translater/`、但里面有 `.sc2transproj` 的文件夹** —— 提示一次「要不要升级成工作区」，
   同意就建 `.sc2translater/`、导入文件清单、**绝对路径能相对化就相对化**（在文件夹内的），
   在文件夹外的保持绝对路径并明确标出来。**原来的 `.sc2transproj` 原样留着不删**。
3. **直接双击/打开 `.sc2transproj`** —— 读它，然后走第 2 条。

迁移只做一次；`.sc2transproj` 的读取代码留一个版本，下个大版本删掉。

仓库目录也要搬：老的 `<项目名>.repos/<文档名>/` 在第一次打开时**移动**进 `.sc2translater/repos/`。
用移动不用复制 —— 仓库里是 git 对象，复制会翻倍占地方。

## 7. 非目标（明确不做）

* **不做多根工作区**（VS Code 的 `.code-workspace`）。单文件夹够用；真出现「地图在两个盘」的需求再说。
* **不在资源管理器里新建 / 删除 / 重命名文件**。这棵树指向的是用户的游戏资源，
  一个误删就是几十 MB 的模组没了。只读。
* **不索引非地图文件**。`.xml` / `.dds` / `.galaxy` 不列，避免大工程里淹掉目标。
* **不做 `.SC2Map` 之外的编辑**。
* 现有的 `sc2trans` CLI 不动 —— 它面向 agent，参数还是绝对路径，跟工作区是两条路。

## 10. 风险

| 风险 | 缓解 |
| --- | --- |
| 路径绝对 -> 相对，写错就把用户的文件清单弄丢 | 迁移**只新增不删除**；迁移前把老项目文件复制一份成 `.sc2transproj.bak`；迁移逻辑有单测 |
| 扫描大文件夹慢（几十 GB 的模组目录） | 深度上限 + 条目预算 + 跳过名单；超预算时在树上标「只显示前 N 项」 |
