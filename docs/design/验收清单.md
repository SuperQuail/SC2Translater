## 1. CLI 冒烟（2 分钟）

```powershell
$map = "D:\Game\BLZ\StarCraft II\Maps\Starcraft Mass Recall\Extras\7. Stukov Series\Stukov2.SC2Map"

# 1) 先看诊断：应当报 zhCN 覆盖率 0%
target\release\sc2trans.exe audit $map

# 2) 导出键
target\release\sc2trans.exe extract $map -o keys.json --json | ConvertFrom-Json | Select-Object -ExpandProperty stats

# 3) 兜底补齐
target\release\sc2trans.exe seed $map --target zhCN -o 'out\Stukov2.zhCN.SC2Map'

# 4) 自检产物
target\release\sc2trans.exe verify 'out\Stukov2.zhCN.SC2Map'
```

通过标准：

* `audit` 的诊断是 `warning`，且指明「未覆盖的键会显示成原始键路径」；
* `seed` 的回读校验通过；
* `verify` 的 `dwRawChunkSize == 0`、HET/BET 逐字节重建为 true、整体健康 true。

## 3. 银河编辑器实机验收（**MPQ 改动的唯一合格判据**）

只要产物的字节变了，就必须过这一关 —— 「合法 MPQ」不等于「SC2 接受」。

可以直接复用上游 SC2Diff 的验收装置（它驱动的是编辑器本体）：

```powershell
python D:\Code\Rust\SC2Diff\tools\editor_accept.py `
  <原件作为对照> <我们的产物> [更多产物…]
```

判定：`LOADED` 才算通过；`CRASH` / `REJECTED` / `TIMEOUT` 都不算。
**必须同时跑一份未改动的原件作对照** —— 否则无法区分「我们的产物有问题」和「这张地图本来就打不开」。

### 手工步骤（不用脚本时）

**这一步自动化不了**（编辑器是自绘 UI 的单实例程序，命令行传文档会直接退出）。步骤：

1. 先把产物放到**独立目录**里，目录里不要有同名文件；
2. 无参启动银河编辑器（`D:\Game\BLZ\StarCraft II\Support64\SC2Editor_x64.exe`）；
3. 文件 -> 打开，在树里选中产物（**对话框里手输路径无效**，必须在树里点）；
4. 若弹「无法加载依赖项数据，仍然继续？」—— 这在依赖缺失时是正常的，选「是」；
5. 按窗口标题是否变成文件路径判定：
   * 标题出现文件路径 -> **LOADED**（通过）；
   * 编辑器进程消失 + `EditorLogs` 下新增崩溃目录（`.dmp` + `Error.txt`）-> **CRASH**（不通过）；
   * 一直没反应 -> **TIMEOUT**。

如果 CRASH，先看 `Error.txt` 里的 `System_Mopaq` 错误链：
历史上出现过 `e_fileCorrupt`，根因就是 `dwRawChunkSize` 被写成 16384。

## 4. 游戏内实机验收（需要人工）

1. 把产物复制到 `%USERPROFILE%\Documents\StarCraft II\Maps`（或战役目录）；
2. 把游戏语言切成**中文**，进入地图；
3. 看三处：
   * 载入界面的地图名 / 作者（`DocInfo/Name`）；
   * 任务目标与提示（`Param/Value/*` 这类键）；
   * 玩家名 / 单位名（`MapInfo/PlayerNN/Name`、`Unit/Name/*`）。

通过标准：**看不到** `Param/Value/xxxxxxxx` 这种键路径。
用 `seed` 兜底后应当显示英文原文；用 `apply` 写回译文后应当显示中文。

## 5. 差分测试（已随 Python 原型一并移除）

调研期用 Python 对照实现做过一次差分：同图中 `extract` 逐字段一致、
`seed` 产物组件逐字节相同（归档整体体积不同 —— zlib 实现不同，属预期）。
那套原型完成使命后已删除，本项**不再需要重跑**；等价保证现在由
`cargo test` 里针对 5 个真实归档的逐字节断言承担。
